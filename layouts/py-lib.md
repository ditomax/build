# Layout profile `py-lib` — Python package, service, CLI tool or batch job

**Status:** reviewed · **Sources:** PyPA packaging guide (src layout, PEP 621 `pyproject.toml`), uv project layout, pytest good practices.

## 1. Skeleton

```
<code_root>/
  AGENTS.md  CLAUDE.md  README.md
  pyproject.toml            PEP 621 metadata, dependencies, tool configuration
  uv.lock                   committed lock file (when uv is used)
  .env.example              every setting by name, no values for secrets
  planning/                 RULES §2 — never inspected by the layout check
  src/<pkg>/
    __init__.py
    __main__.py | cli.py | app.py   entry point / composition root
    core/                   shared kernel: config.py, errors.py, domain types used by ≥ 2 features
      __init__.py
      config.py             from layouts/_tools.md
    <feat>/                 one package per build feature (feature code in lower case)
      __init__.py           the feature's public interface — the only import path for other features
      <module>.py           one responsibility each (guideline L6)
  tests/
    architecture/test_layout.py     from layouts/_tools.md
    <feat>/test_<module>.py         unit tests, mirrored by feature
    integration/test_<slice>.py     one file per vertical slice
    fixtures/                       synthetic data, golden outputs (versioned)
  tools/
    dev.py                  from layouts/_tools.md
    secret_check.py         from templates/repo-hygiene.md (H5)
  scripts/                  deploy, seed, migrate, rollback, smoke (→ planning/build/deployment.md)
```

## 2. Mapping

| build term | In this profile |
| --- | --- |
| feature | package `src/<pkg>/<feat>/` |
| core | package `src/<pkg>/core/` — never imports a feature |
| entry point / composition root | `src/<pkg>/__main__.py`, `cli.py` or `app.py`: reads the configuration, wires the features, starts |
| public interface of a feature | what `src/<pkg>/<feat>/__init__.py` imports and lists in `__all__` |
| module (concept §11) | one `.py` file with one responsibility |

## 3. Dependency rule and its check

Entry → features → core. A feature imports another feature only as `from <pkg>.<other> import <name>` (a name its `__init__.py` exports), never `from <pkg>.<other>.<module> import …`. Core imports no feature and no entry module. Enforced by `tests/architecture/test_layout.py` (CONFIG: `PKG = "<pkg>"`, `ALLOWED_TOP` from the layout ADR). Optional and stricter: import-linter with a `layers` and an `independence` contract — a dependency, so the user decides (Y2).

## 4. Tests

| Kind | Location | Runner | One test |
| --- | --- | --- | --- |
| unit | `tests/<feat>/test_<module>.py` | pytest | `python tools/dev.py test tests/<feat>/test_<module>.py::test_<name>` |
| integration | `tests/integration/test_<slice>.py` | pytest | `python tools/dev.py test -k <slice>` |
| layout | `tests/architecture/test_layout.py` | unittest / pytest | `python tools/dev.py check` |
| fixtures, golden outputs | `tests/fixtures/<feat>/` | — | regenerated by a tool in `tools/`, registered in `agent-testing.md` |

CI constraints (MANIFEST Phase 7): no network, no LLM calls; external services are mocked behind the feature's own adapter module.

## 5. Execution surface

`tools/dev.py` PROFILE block:

```python
PKG = "<pkg>"
TEST = [sys.executable, "-m", "pytest"]
LAYOUT = [sys.executable, "-m", "unittest", "tests.architecture.test_layout"]
LINT = [["ruff", "check", "."]]
TOOLS = ["uv", "pytest", "ruff", "gitleaks", "pre-commit", "git"]
REQUIRED = ["git", "pyproject.toml"]
```

Environment: `uv sync --extra dev` (or `python -m venv .venv && pip install -e .[dev]`) — an install, so it needs the user's yes (Y0).

## 7. Agent limits

None typical — Python, pytest and ruff run in any sandbox. Installs (uv, dependencies) need the user's yes.
