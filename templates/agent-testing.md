# Agent Testing Manual

_The memory of everything an agent needs to test this project: which tools exist and how to call them, where test data comes from, which failures were already solved and how. **Read it before writing any test, fixture or helper tool** — reuse beats rewriting. Update it **in the same commit** as the code it describes. Lives with the code (`planning/build/`), replaces the former `test_tooling.md`. The gap analysis (MANIFEST Phase 9) checks section 1 in both directions (orphans, ghosts) and section 2 against the CLI's `--help`._

## 1. Tool register

Every test runner, fixture generator, debug helper, inspection script and diagnostic command. A tool is registered in the same commit that adds it; a deleted tool is marked `obsolete (reason)` in the same commit.

| Name | Purpose | Invocation (copy-paste, from the repo root) | Key parameters | Environment & preconditions | Status |
| --- | --- | --- | --- | --- | --- |
| dev CLI | test, check, configuration, environment | `python tools/dev.py <command>` | see section 2 | Python 3.11+; no network | active |
| | | | | | |

**Column guide** — Environment & preconditions: target env (dev / stage / prod), LLM or network calls (yes / no), required mocks, test data location, env var names (never values). Status: `active` | `obsolete (reason)`.

## 2. CLI quick reference

The commands agents use daily. The full reference is `cli.md` (generated); keep this list short and in sync with it.

| Task | Command |
| --- | --- |
| run all tests | `python tools/dev.py test` |
| run one test | <profile: e.g. `python tools/dev.py test tests/<feat>/test_<module>.py::test_<name>`> |

| show the configuration (secrets masked) | `python tools/dev.py config show` |
| check the environment | `python tools/dev.py doctor` |
